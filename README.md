# CS 360 Mobile Application Portfolio

**Inventory Manager App – Project Three**

## Project Overview

In order to develop the Inventory Manager app (Project Three), I utilized Android Studio and Java. The objective of the app was to build a straightforward inventory management application. As such, it has several functions. Users may register for an account and then log in to the app. After they have logged in, they are able to enter data about each item in their inventory, update the number of each item in stock, as well as remove items from inventory. To assist in managing inventory, the app utilizes SQLite to save all pertinent data regarding user accounts and inventory. Furthermore, the app can send SMS messages when a product reaches zero quantity.

## User Interface Design

The Inventory Manager app contains four screens. They include: Login Screen, Inventory Screen, Add Item Screen, and SMS Notification Screen. I chose to utilize a blue and white color scheme because it provided a clean and easy-to-read format. I wanted users to be able to easily find what they needed and get started with taking care of their inventory needs quickly and efficiently. Overall, I feel that I was able to achieve this based on the fact that I had no problem finding what I needed or completing inventory-related tasks while utilizing the app during testing.

## Development Approach

When developing the Inventory Manager app, I took the approach of creating and testing individual pieces of functionality within the app. The primary tool that I used for developing the app was Android Studio. I used Java for the majority of the code and SQLite to provide storage for user account data and inventory data. A lesson that I learned throughout this experience was the value of making small changes one at a time and thoroughly testing them before combining them. Going forward, I wish to utilize an even better development approach than the one I used in this project. In addition, I want to ensure that I maintain a working version of my app at all times before implementing new features.

## Testing and Functionality

To test my Inventory Manager app, I utilized the Pixel 7 Android Emulator. First, I registered a user account for myself. Then, I successfully logged in. Next, I added multiple products to my virtual inventory. I then increased and decreased the quantities of these products. Afterward, I removed products from inventory. I also verified that user account information and inventory data remained saved after closing the app and logging back in. Additionally, I confirmed that my app successfully sent an SMS notification when a product reached zero quantity. These tests were crucial because they allowed me to discover errors or problems that might not have been apparent otherwise.

## Problems/Challenges and New Ideas

A major issue that I faced during this project was improving the SMS notification feature, as well as adding other capabilities after the initial version of the app functioned properly. Unfortunately, the updated version contained a bug that made it impossible for me to launch it. Although challenging, this taught me that adding new functionality can negatively impact existing functionality. Most importantly, it showed me how imperative it is to perform tests after each adjustment to ensure functionality remains intact, as well as keep a functional copy of my work.

## Displaying My Abilities

In terms of demonstrating my skills with respect to integrating SQLite databases and providing inventory management functionality, I felt very confident. I am proud of being able to establish a system where users can add, modify, view, and remove products from their inventory while saving all relevant product data between sessions. Through doing so, I effectively demonstrated my understanding of database integration concepts, Java programming, and mobile application development using technologies including Android Studio and SQLite.
